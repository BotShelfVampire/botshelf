# BSV binding decisions — compact ledger

- Existing Trader category is expanded; do not create a duplicate.
- AI category and Trader category both need major content growth.
- Trader end-state: BSV should let a motivated user build a personal chart tool with minimal coding.
- Add innovative reusable blocks/recipes/generators, not only a directory of platforms.
- Dots and Hugging Face are active AI expansion targets.
- Vela is a high-value custom-chart path.
- Third-party proprietary code must not be copied.
- Explicit compatible licenses are required for third-party source redistribution; otherwise create original source from public APIs/math.
- Verification must remain exact and scoped.
- Do not over-rely on local AI.
- LM Studio is available locally and should be used for cheap low-risk work where useful.
- Reduce ChatGPT/GrokBot token use with deterministic tooling, compact shared context, caching/routing where clients permit, and no duplicate reasoning.
- Owner should not need to intervene in routine execution.
- Toolkit summaries are public. BSV toolkit source (trader + AI) is served only behind the email-verified session gate (`/trading/items|downloads/bsv-*`, `/library/source/*`). Catalog status is shown verbatim, and Runtime-tested stays 0 without evidence.
- Live toolkit pages are generated by `scripts/site/build_live_toolkit.py` from the catalogs. Nobody edits that HTML by hand.
- Netlify CLI deploy layout keeps `netlify/`, `netlify.toml` and `node_modules` outside the publish dir. Deploy with `--prod` (production context). Never publish a CLI draft via `restoreSiteDeploy`: drafts run in `deploy-preview` context without production-only env (SMTP/operator email) — this broke OTP registration 16:04–16:23 JST on 2026-10-03.
- Site CSS/JS are `immutable`. Changed assets need new file names (content hash).
- New toolkit surfaces use the green accent, not gold.
- The 70 Library team implementations follow the source rule: explanation/files/examples public; full prompt/config/code only at `/library/source/team-*.html` behind the verified session; still labelled free. `items.json` carries no bodies.
- `*.bak*` backups and generator scripts are build artifacts, not site content; `gate_library_bodies.py` prunes them from every deploy tree (some held gated pages).
- The recipe builder is gated as BSV source: page `/trading/items/bsv-builder.html`, generator port under `/trading/sources/`. Its output must stay byte-identical to `render.mjs` (parity test).
- Logged-in QA uses the operator test account (`support@botshelfvampire.com`, name `OTP test`); its cookie jar stays on the box.
- Library pack items (skills, kimi-*, gemini, deepseek, cursor, claude-code, dify, flowise, autogen, openrouter, agentswarm, mcp, …) use the same body gate as the 70 teams: public explanation; full text at `/library/source/item-<runtime>-<slug>.html`; free label kept. `gate_library_bodies.py --packs all`.
- Trader generator/builder targets include MQL4, cTrader Python and Bookmap Python alongside Pine v6 / MQL5 / cTrader C#. Catalog status stays UNTESTED_RUNTIME until runtime evidence exists.
