- 2026-10-04 (owner hint: cTrader HTF via GetIndexByTime(currentOpenTime) - 1): **implemented with a guard; the bare hint was not enough.** The official reference does not define how `TimeSeries.GetIndexByTime` resolves a time inside a bar (https://help.ctrader.com/ctrader-algo/references/Collections/DataSeries/TimeSeries/ only says "Find the index in the different time frame series"); Spotware staff on the forum describe it as the *nearest/closest* bar. Under floor rounding `k - 1` is closed, but under nearest or ceiling rounding `k` can be the HTF bar *after* the one containing the chart bar (it exists in history), so `k - 1` would be the containing bar, i.e. lookahead on historical bars. Fix used: `k = GetIndexByTime(t)`, clamp to `Count - 1`, then `while (k >= 0 && htf.OpenTimes[k] > t) k--` (documented OpenTimes indexer) so bar k opened at or before the chart bar's open time t; bar k - 1 then ended at OpenTimes[k] <= t and is closed under ANY rounding (worst case one extra HTF bar of lag when the result is earlier than the containing bar; -1 or empty series gives NaN). Bars via `MarketData.GetBars(TimeFrame.Hour)` (https://help.ctrader.com/ctrader-algo/references/MarketData/MarketData/); indicators on that series (`ExponentialMovingAverage(bars.ClosePrices, n)`, `AverageTrueRange(Bars, n, MovingAverageType)` per IIndicatorsAccessor reference); TimeFrame names from https://help.ctrader.com/ctrader-algo/references/Period/TimeFrame/ (no ordering operator is documented, so the guard is `Array.IndexOf(<strictly lower time frames>, TimeFrame) >= 0`; otherwise values stay NaN and a Print explains). Signals with an HTF input require non-NaN values. `check_htf.py` enforces the helper, the HTF input, the guard list and no chart-index/newest reads, with 7 mutants (incl. the bare unguarded GetIndexByTime); `check_ctrader_stubs.sh` compiles all 14 recipes against stubs from the API reference (coverage check kind STUB_COMPILE).
