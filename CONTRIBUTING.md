# Contributing to BotShelf Vampire prompt packs

Useful contributions make a specific job easier to run or verify: a corrected instruction, clearer input contract, small example, or tested adaptation.

1. Check files and open issues or pull requests for the same change.
2. Keep the contribution focused on one job or fix.
3. Explain the problem and change. Attribute the original source and check its license.
4. If you claim a workflow ran, include redacted input and actual output, runtime/model details, source revision, and limitations. If you only checked the text, say so.
5. Use fictional or permissioned data. Exclude credentials, private messages, customer records, and fabricated results.
6. Open a pull request with that context. Keep unrelated promotion out.

Improving free source files does not submit a commercial product. Use the [seller guide](docs/sellers.md) for Marketplace requirements and the private submission route.

## Useful pull request details

```text
Job or bug:
Before / after:
Files changed:
Validation actually performed:
Runtime/model and source revision (if run):
Input and actual output (redacted):
Known limits / failed cases:
Source attribution:
```

Label structural checks, illustrative outputs, and live runtime tests separately. One test does not justify a global "verified" claim.
